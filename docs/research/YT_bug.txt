YouTube now blocks requests that don't look like they are coming from a "verified" device.

Here is how to fix this:

### 1. The "Protocol" Fix (Most Likely Cause)

The plugin has different "Clients" it can mimic (Web, Android, iOS, TV). If it’s trying to use the **Web** client without a valid session, YouTube returns "Unavailable."

### Why the Anonymizer/Incognito failed

In your logs, the error happens at `load_stream_info`. When you are in "Incognito" or using an outdated "Anonymizer," the plugin sends a "Visitor Data" string to YouTube. If that string isn't signed by a recent Google security token, YouTube triggers a "soft-block" and tells the plugin the video doesn't exist.
