**No duplicates with existing scripts** - qs.sh is distinct: it's a *session initializer*, not a builder/linter/syncer.

**What qs.sh should do (your case):**
Assemble a ready-to-paste AI context file from existing sources:

- `system/config/ai_protocol.yaml` - base rules
- `system/modes/[active_mode].yaml` - current mode
- `system/roles/` - active role
- `share/handoffs/` - latest handoff
- Filtered tree (projects + scripts only, no logs/zips)

**Two approaches:**

**A. Single dynamic quickstart** - qs.sh assembles everything fresh each run into one file. Flexible, always current.

**B. Mode-specific templates** - `qs_coding.sh`, `qs_brainstorm.sh` etc. Pre-structured per context. Less flexible, faster to grab.

**My advice:** A + light templating. One `qs.sh` with optional mode argument:
```
qs.sh           # default/last mode
qs.sh coding    # pulls coding mode config
```
Output: `share/quickstart_[mode]_[ts].txt`
